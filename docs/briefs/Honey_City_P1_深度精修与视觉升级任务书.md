# HONEY CITY｜P1 深度精修与视觉升级任务书

**版本：** P1.0  
**审查对象：** `honey-city(1).html` + `TEST_REPORT.md`  
**审查日期：** 2026-10-31  
**任务性质：** 在现有 React/Vite 原型基础上做第二阶段精修；保留现有信息架构与交互，不推倒重做。  
**本轮核心：** 从“功能完整的游戏风格 UI 样本”提升为“具有明确《明日方舟》视觉语法、真实游戏界面层次、可研究可复用的 UI/Motion 设计系统”。

# 0. 审查结论与执行方向

## 0.1 当前版本做得好的地方

当前版本已经有了可继续投资的基础：

- React 18 + Vite 构建，页面按组件组织，不再是早期单文件手写 DOM 的原型。
- 有首页、频道索引、频道详情、终端、设计实验室五个核心场景。
- 有统一的转场 Provider，使用 Web Animations API 管理页面转场。
- 已实现 mask、slices、zoom、wipe、shared 五类页面转场。
- 页面路由与浏览器历史记录有基本同步。
- 抽屉、弹窗、移动导航具备键盘关闭、焦点管理等基础能力。
- 设计令牌已有颜色、字体、字阶、间距、尺寸、动效时长与缓动曲线。
- 视觉风格有一致性：深色底、暖琥珀强调色、克制的网格/切角/标签系统。
- 测试报告记录了 14 项功能测试通过、25 个视口与路由组合无横向溢出、20 张截图流程、控制台 0 error / 0 warning。

## 0.2 当前版本真正的瓶颈

当前问题已经不是“有没有页面、按钮能不能点”，而是：

1. **视觉语言还不够独特。** 深色工业风、琥珀强调色、左侧导航轨道和面板布局完成度不错，但仍容易被看成一套通用的暗色产品终端。需要更鲜明的主题构图、频道图形和游戏内 UI 的叙事性。
2. **页面节奏偏平均。** 很多区域沿用相似的面板、标签、分隔线和信息排列，缺少真正的主次变化与强弱节奏。
3. **视觉资产不足。** 目前主要依赖 CSS 几何、网格和 SVG 小图形，缺少能够成为页面记忆点的原创频道徽记、主视觉图形和场景化插画。
4. **实验室仍偏展示型。** 已有参数、曲线和预览，但尚未形成“观察—调整—对比—复用”的完整动效研究工具。
5. **设置状态仍有边界问题。** 减少动态的系统偏好只在初始化时读取；站内减少动态开关没有与全部 CSS 微动效统一；速度/模式/减少动态不持久化。
6. **交付形态不完整。** 当前收到的是 300KB 左右的构建产物 HTML，而不是原始 React/TSX/CSS 源码项目。可以检查成品行为与部分实现，但不适合直接开展长期维护级修改。

## 0.3 本轮原则

- 不删除五个核心页面。
- 不改变“UI 与动效研究样本”的项目定位。
- 不加入竞猜、积分、NPC、奖励、淘汰、账号或后端玩法。
- 不通过堆叠线框、随机数字、伪代码来制造科技感。
- 不追求每个页面都塞满信息；允许大面积留白，但必须有视觉目的。
- 以《明日方舟》游戏 UI 的信息组织、面板层级、状态反馈、图形符号与动效节奏为研究对象，不声称逐像素复刻官方界面。
- 优先用原创 SVG / CSS 图形构建视觉资产，避免无授权素材与不匹配的 AI 插画。

## 1.2 需要优先核对的实现细节

以下为对当前构建 HTML 的静态代码审查发现，不代表已经在真实浏览器中复现：

### A. 转场错误被静默吞掉

转场调用链存在 `.catch(()=>{})` 一类的空错误处理。转场失败时，用户可能只看到动画中断或页面状态不符合预期，开发者也无法从控制台定位原因。

**修订要求：**
- 开发模式记录完整错误与转场类型、目标路由、阶段。
- 生产模式可降级为无动画直接切页，但不能静默丢失导航。
- `finally` 必须保证遮罩、滚动锁、临时节点和状态全部清理。
- 只有当前任务 ID 可以提交路由与释放当前转场状态。

### B. 活动动画引用的生命周期

转场 Provider 会注册动画实例，并在下一次转场或取消时统一取消。建议在每个动画完成 / 取消时同步从活动集合移除，避免不必要地保留已结束对象。

**修订要求：**
- 动画注册返回 disposer，或在 `finished.finally()` 中自动移除。
- 每次转场有独立任务上下文。
- 旧任务不得清理新任务的遮罩或滚动锁。
- 共享元素临时隐藏、克隆节点、临时样式都使用 `try/finally` 恢复。

### C. 减少动态设置未完全统一

当前系统偏好通过 `matchMedia('(prefers-reduced-motion: reduce)')` 在初始化时读取；站内开关可以控制转场降级，但需要进一步确认 CSS 微交互是否同步。

样式表里存在 `html[data-reduce=true]` 的降级规则，但当前构建脚本中未发现明确设置该根属性的逻辑。系统级 `@media` 能覆盖系统偏好，却不能保证站内手动开关同时关闭所有 CSS 动画。

**修订要求：**
- 使用 `system / reduce / full` 三态策略。
- 监听 `MediaQueryList` 的 `change` 事件。
- 将最终状态同步到 `document.documentElement.dataset.reduce`。
- 所有 WAAPI、CSS transition、keyframes、页面入场、骨架屏、Toast、按钮反馈读取同一最终状态。
- 减少动态开启时，不能只把大转场改为淡入，而保留无限循环流光或大幅位移。

### D. 弹层的背景隔离

当前抽屉和弹窗已有 `role="dialog"`、`aria-modal`、Tab 焦点循环和 ESC 关闭。还应将弹层外的主应用区域设为 `inert`，并在关闭时恢复。

**修订要求：**
- 弹层打开后，背景不能被键盘、鼠标或辅助技术访问。
- 关闭后恢复原始 `inert` / `aria-hidden` 状态。
- 记录真正的触发元素，而不是仅依赖弹层挂载时的 `activeElement`。
- 嵌套弹层采用栈管理，避免一个弹层关闭时误解除另一个弹层的隔离。
- 处理触发按钮已卸载或隐藏时的焦点回退。

### E. 运行设置没有持久化

测试报告已经明确记录速度、模式、减少动态只保存在当前会话，刷新恢复默认。

**修订要求：**
- speed、quick、用户主动设置的 motion preference 使用 `localStorage`。
- 系统跟随模式不应被误保存为“强制减少”。
- 存储读取失败时安全回退。
- 提供“恢复默认设置”入口。
- 不保存用户输入的敏感内容；本项目没有必要引入账号或云同步。

# 2. P1-1：建立更明确的视觉艺术指导

## 2.1 从“暗色工业面板”升级为“游戏内活动终端”

当前视觉语言的优势是克制、清楚、统一；问题是大量组件共享相近的深色面、细分隔线、琥珀强调和英文标签，容易产生模板化。

下一阶段要建立三层视觉语法：

### 第一层：世界观 / 场景层
负责让人一眼记住“蜜果城”：
- 具有识别度的城市 / 赛区 / 信号网络图形。
- 四个频道各自的徽记、几何母题、纹理与局部构图。
- 首页主视觉不再只是大标题 + 网格背景；要有明确主体和视觉叙事。
- 主视觉应有近景、中景、远景或图形层次，但不必使用写实插画。

### 第二层：界面结构层
负责真实游戏 UI 的可读性：
- 顶部全局状态与当前区域信息。
- 侧边导航、页面标题、内容分区、面板、列表、标签、状态。
- 信息密度有主次，重要状态比装饰更突出。
- 页面切换时，导航与内容区的状态变化清楚。

### 第三层：反馈 / 动效层
负责交互手感：
- hover、focus、pressed、selected、disabled、loading、success、warning、error 的状态语言一致。
- 频道色只作为局部语义，不把整张页面染成单一主题色。
- 转场应服务于“进入频道 / 深入档案 / 切换终端”等语义，而非单纯展示特效。

## 2.2 建议建立四个频道的视觉母题

每个频道需要拥有自己的视觉符号和图形语言，而不只是一个不同的强调色。

| 频道 | 视觉母题建议 | 图形语言 | 色彩方向 |
|---|---|---|---|
| 争锋频道 | 对抗、广播、中央塔、信号锁定 | 交叉轴线、瞄准环、斜向切割、双向箭头 | 暖琥珀为主，少量警示红 |
| 蜂巢回廊 | 设备、蜂巢结构、检修通道 | 六边形模块、节点连线、重复栅格 | 冷青灰、低饱和蓝 |
| 蜜露档案 | 纸档、胶片、记录、时间 | 索引标签、档案编号、页签、胶片孔 | 陶土红、旧纸白、灰褐 |
| 甜品工坊 | 制作、配方、器具、工序 | 刻度、配方表、圆形计量、模块拼接 | 苔绿、奶油白、深墨色 |

要求：
- 频道徽记必须是可复用的 SVG 组件。
- 每个频道至少有 1 个主徽记、2 个辅助图形、1 种背景纹理。
- 不要直接用 emoji 替代图标。
- 不要把四个频道做成四套完全不同的 UI；保持同一套组件骨架。

## 2.3 视觉比例与排版

- 统一桌面内容区的最大宽度、侧栏宽度和左右安全边距。
- 页面标题、英文副标题、说明、元信息建立固定比例。
- 避免每页都使用同一种“标题 + 横线 + 卡片网格”结构。
- 首页使用非对称构图；频道索引使用有节奏的磁贴；详情页使用主题化头图与内容分区；终端使用信息流；实验室使用工具台布局。
- 标题字号不要只追求大；应有 Display / H1 / H2 / Body / Caption 的实际使用规则。
- 中文正文行宽控制在易读范围；英文标签只保留必要信息。
- 数字统一使用等宽数字，避免实时状态与计数跳动。

# 3. P1-2：首页与页面构图深度升级

## 3.1 首页

当前首页已经有品牌、标题、说明、入口与视觉网格，但还需要形成真正的主视觉焦点。

必须完成：
1. 设计一张原创的“蜜果城信号总览”主图形，优先 SVG。
2. 主图形由 3–5 个有语义的层次构成：城市轮廓 / 中央塔 / 频道信号 / 频道徽记 / 信息标注。
3. 主标题与图形之间形成构图关系，不要把图形当成标题旁边的装饰。
4. 增加“当前区域 / 当前信号 / 样本版本 / 非官方演示数据”信息，但控制数量。
5. 首页入口应有主次：一个主入口，其他入口作为次级探索。
6. 首页下半部不要重复首页首屏的卡片布局；用频道走廊或专题导航形成节奏变化。

## 3.2 频道索引

- 四张频道磁贴使用不同的图形构图与视觉母题。
- 统一编号、名称、英文名、简介和状态位置。
- hover 不只做颜色变亮；可以通过徽记旋转、几何边界展开、局部遮罩或信息显现形成反馈。
- 选中态应能在静态截图中被识别，不依赖 hover。
- 频道卡片的可点击区域必须完整，键盘焦点样式独立于 hover。

## 3.3 频道详情

- 顶部应形成“频道识别区”：徽记、频道名、状态、频道代码、简短说明。
- 详情内容不应只是多个相似面板纵向排列。
- 赛程 / 资料 / 公告等内容按信息类型设计不同结构。
- 当前频道主题色只作用于关键状态、局部边界、标识，不要大面积铺色。
- 增加频道间切换的上下文连续性，例如同一位置的徽记 / 标题共享元素。

## 3.4 终端

- 终端应该像“档案与信息终端”，而不是普通表格后台。
- 筛选、搜索、分页、状态标签保持紧凑。
- 重点条目允许采用时间轴、信息卡、列表行等不同结构。
- 列表与详情的视觉关联要明确。
- 增加空状态、加载状态、错误状态和无结果状态的统一设计。
- 所有演示数据在页面可见位置标记为 `SAMPLE DATA`，避免误认成官方设定。

## 3.5 设计实验室

实验室不应只是把组件放在一页，而是一个有明确工作台逻辑的研究空间：
- 左侧：实验分类 / 当前样本。
- 中央：实时预览区域。
- 右侧：参数、令牌、说明与复制结果。
- 窄屏时改为纵向流程，不要把桌面三栏直接压缩。
- 组件状态、转场、曲线、色板分别成组，避免过长的单列信息墙。

# 4. P1-3：动效系统从“转场集合”升级为 Motion Director

## 4.1 统一动效层级

建议建立以下动效层级：

| 层级 | 内容 | 建议时长范围 | 原则 |
|---|---|---:|---|
| M0 | 即时反馈：按下、勾选、焦点 | 60–120ms | 不拖延操作 |
| M1 | 微交互：hover、状态、图标 | 120–200ms | 轻、短、明确 |
| M2 | 局部组件：Tab、卡片展开、抽屉 | 180–320ms | 有方向和因果 |
| M3 | 页面入场 / 内容重排 | 280–460ms | 先主后次 |
| M4 | 页面级转场 | 420–720ms | 有主题、有节奏，不频繁播放 |

时长不是越长越好；必须在实际内容长度、用户等待感与视觉表达之间平衡。

## 4.2 五种转场的深化方向

| 转场 | 当前定位 | P1 深化 |
|---|---|---|
| mask | 多层几何遮罩 | 遮罩分层与页面主题联动；标签不抢主视觉 |
| slices | 分片拼接 | 切片宽度不必完全相等；加入合理错峰，避免机械百叶窗 |
| zoom | 锚点聚焦 | 锚点来源、目标中心、缩放幅度和回弹统一计算；小屏避免过度缩放 |
| wipe | 方向擦入 | 与导航方向 / 内容流方向保持一致，进入与退出形成呼应 |
| shared | 共享标题 | 支持标题、徽记、编号等多个共享节点；匹配字体尺寸、基线和边界 |

所有转场必须：
- 有统一的开始、覆盖、提交、揭示、清理阶段。
- 任何阶段都能被新导航安全打断。
- 取消后无残留节点、内联样式、滚动锁或隐藏元素。
- 异常时立即降级为无动画切页。
- 不能把页面转场与组件内动画混成一个不可控时间轴。

## 4.3 Motion Director

新增统一控制层，职责包括：
- `MotionTokens`：时长、曲线、距离、缩放、错峰参数。
- `MotionPreference`：系统 / 减少 / 完整三态。
- `TransitionTask`：每次转场独立 ID、取消信号、清理函数。
- `MotionRegistry`：跟踪当前动画与可取消任务。
- `MotionDebug`：开发模式记录转场阶段、耗时、取消原因与异常。

禁止：
- 每个组件随意写一套新的 cubic-bezier。
- 多个动画任务同时控制同一个元素。
- 通过长时间锁住所有交互来保证动画不被打断。

## 4.4 实验室动效工具升级

P1 必须增加：
- 当前转场的阶段提示：Cover / Commit / Reveal / Cleanup。
- 播放、重播、暂停、继续、复位。
- 速度倍率与减少动态状态实时显示。
- 当前曲线的可视化与参数值。
- 转场方向选择。
- 一键复制当前 easing / duration / CSS 变量。
- 预览结束后自动清理所有临时节点。

P1 可选：
- 逐阶段单步播放。
- 多种曲线 A/B 对比。
- 记录一组预设并恢复默认。
- 将实验参数导出为 JSON。

# 5. P1-4：设计令牌与主题系统

## 5.1 颜色令牌

保留现有深色主主题，但将颜色按语义组织，而不是只按表面深浅组织：

- `canvas`：页面背景。
- `surface-1 / 2 / 3`：内容承载、浮层、强调面。
- `ink-primary / secondary / tertiary`：文字层级。
- `line-subtle / normal / strong`：结构线。
- `accent-primary / accent-soft / accent-contrast`：主题强调。
- `status-live / success / warning / danger / info`：状态色。
- `channel-arena / hive / archive / workshop`：频道语义色。

不要在组件里硬编码颜色。频道主题应通过 CSS variables 注入。

## 5.2 第二套主题

新增“档案纸面 / Paper Dossier”对照主题，而不是简单反相：
- 暖灰纸面作为画布。
- 深墨色作为正文。
- 低饱和琥珀作为主强调。
- 频道色整体降低饱和度。
- 纹理可以有轻微纸张颗粒，但必须保证文字对比度。
- 所有图表、按钮、标签、弹层、导航都要有对应主题值。

## 5.3 持久化

- 主题、速度、转场模式和减少动态用户偏好持久化。
- 系统跟随模式与用户强制覆盖必须区分。
- 提供“恢复默认”。
- 首次加载避免主题闪烁。
- `localStorage` 不可用时不影响应用运行。

# 8. P1-7：无障碍、响应式与性能

## 8.1 无障碍

- 弹窗 / 抽屉打开后背景 inert。
- 焦点进入弹层、在弹层内循环、关闭后归还。
- 读屏标题与描述关联正确。
- 状态不能只通过颜色表达。
- 所有交互控件有明确可访问名称。
- 触屏不依赖 hover 才能触发核心功能。
- 减少动态开关与系统偏好一致。

## 8.2 响应式

当前报告覆盖 1440、1280、1024、768、390px。P1 必须补测：
- 1920×1080；
- 1440×900；
- 1024×768；
- 820×900；
- 768×1024；
- 430×932；
- 390×844；
- 360×800。

重点检查：
- 左侧导航轨道与移动导航切换。
- 首页主视觉在窄屏的顺序与比例。
- 频道磁贴高度与信息截断。
- 详情页多列面板堆叠。
- 终端筛选区、列表和详情的顺序。
- 实验室预览与参数区。
- 弹窗、抽屉、Toast 和键盘弹出时的可用空间。

## 8.3 性能

- 重点动画优先使用 transform / opacity。
- 限制大面积 filter、backdrop-filter、复杂 clip-path 的同时使用。
- SVG 纹理避免重复创建大量节点。
- 动画完成后释放引用。
- 低端移动设备下提供减少切片数量与降低纹理层数的策略。
- 记录主要转场的耗时与帧率表现；没有真实设备测试时明确标注。
